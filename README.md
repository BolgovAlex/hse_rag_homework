## Как работает

PyMuPDF извлекает текст по физическим страницам PDF, сохраняет `doc_id`, организацию и номер страницы от 1. Таблицы с распознанными границами дополнительно переводятся в Markdown; для сканов используется OCR rus+eng. Если обычное OCR не сработало, проверяются повороты на 90°, 270° и 180° без изменения исходного PDF. Непрочитанная страница не превращается в пустой контекст. Разобранные документы сохраняются отдельно с проверкой версии парсера и SHA-256 PDF, поэтому после сбоя не нужно повторять весь разбор.

Поиск объединяет BM25 с простой нормализацией русских окончаний и косинусную близость локальных векторов: символьный TF-IDF → SVD, до 192 измерений. Нормализация применяется только к поисковым токенам; контекст сохраняет исходные числа, знаки и единицы. Это локальные LSA-векторы, **не нейросетевые эмбеддинги**. Они строятся только по PDF и не расходуют API-квоту. Название банка ограничивает поиск по организациям, год и тип отчёта дают мягкую прибавку: сравнительные данные могут находиться в более позднем отчёте.

Для распознанных двухколоночных текстовых страниц берутся связные PDF-блоки, для таблиц сохраняются строки. Обычные разрядные пробелы и десятичные запятые сохраняются; широкие отступы эвристически трактуются как границы столбцов. Выдержки выбираются по содержательным словам вопроса с учётом границ строк и продолжений, без обрыва числового токена на разрядном пробеле; суммарный бюджет текста остаётся 10 000 символов.

Генератор `deepseek-flash` получает найденные выдержки. Он сам решает, отвечать сразу или выполнить до двух дополнительных запросов. Второй раунд завершает ответ. В `context` возвращаются все страницы, показанные модели в обоих раундах. Разметка `gold_*` доступна только оценщику после ответа.

Зависимости: PyMuPDF, scikit-learn, NumPy/SciPy, requests, openpyxl и joblib. Исходный файл `eval/eval_functions.py` сохранён без изменений, включая модель и промпт судьи.

## Запуск

Нужен Python 3.10+ и интернет для корпуса и курсового шлюза. Ключ `LLM_API_KEY` задаётся в `.env` по примеру `.env.example`; из архива он исключён. `EMB_KEY` в этой реализации не нужен.

Из папки проекта:

```bash
python run_homework.py
```

Команда создаёт отдельное окружение, устанавливает зависимости, запускает офлайн-проверки, скачивает исходные PDF и OCR-данные с проверкой контрольных сумм, строит индекс и проверяет поиск на первых 24 train-вопросах. **Вызовов LLM на этом этапе нет.**

Для проверки сдачи после подготовки запустите eval с отдельным именем файла. Команды для Windows приведены ниже.

```powershell
.\.venv\Scripts\python.exe -m evaluate --split test --output artifacts/test_repeat.xlsx --no-readme
.\.venv\Scripts\python.exe check_repeat.py test_results.xlsx artifacts/test_repeat.xlsx
```

На Linux и macOS используйте `.venv/bin/python` вместо `.\.venv\Scripts\python.exe`. Для продолжения прерванной проверки добавьте `--resume` к первой команде. Флаг `--no-readme` сохраняет в README средние сданной серии.

Для создания новой сдаваемой серии из папки без `test_results.xlsx`, с уже готовым индексом:

```bash
python run_inference.py --smoke
python run_inference.py
```

Для отдельного повторного smoke после изменения системы: `python run_inference.py --smoke --tag v2`. Предыдущая серия сохраняется.

`run_inference.py` сам выбирает готовое `.venv` и папку проекта. Для продолжения той же незавершённой серии добавьте `--resume`.

Или вручную в подготовленном окружении:

```bash
python -m evaluate --split test --output test_results.xlsx
```

В `test_results.xlsx` будут все 141 вопрос, десять обязательных колонок, четыре средних и отдельный лист с объяснениями судьи. Время измеряется от получения вопроса готовым RAG до полного ответа; поиск, ожидание лимитера и генерация включены, загрузка индекса и судья исключены. Ответы не берутся из кэша прошлой серии.

Контрольные результаты пишутся после каждого вопроса. Если временно недоступен API или закончилась квота:

```bash
python run_homework.py --run --resume
```

Resume сверяет датасет, код, индекс и настройки. Ответ, уже полученный до сбоя судьи, сохраняется и не генерируется повторно. Изменение конфигурации требует новой серии с другим `--output`.

Для отладки разрешён только train, например:

```bash
python -m evaluate --split train --limit 8 --output artifacts/train_results.xlsx
```

## Квота и повторяемость

Генератор и судья используют один лимитер: не чаще одного запроса в 6,2 с, максимум 10 за скользящие 60 с. Счётчик защищён от одновременных процессов в этой папке. Защитный бюджет — 1,7 млн токенов за скользящие 24 часа, без предположения о часовом поясе сброса квоты сервера. Расход берётся из ответа шлюза. При неизвестном `usage` сохраняется консервативная резервация. Журнал в `.private/` и ключи не сдаются. Внешние запуски с тем же ключом журнал не учитывает.

Обычный прогон test требует от 282 до 423 обращений с учётом генерации, судьи и дополнительного поиска. Если модель после поиска не возвращает ответ в ожидаемом формате, программа делает одну финальную попытку с уже найденными источниками и просит ответить обычным текстом. Контекст ограничен 10 000 символов на раунд. Расход контролируется по ходу прогона.

Первый прогон остановился на вопросе №133 из-за формата ответа модели. Первые 132 строки получены до добавления запасной попытки. Их сохранили и продолжили с вопроса №133. Хеши обеих версий и сохранённого фрагмента записаны в [`test_run_provenance.json`](test_run_provenance.json).

Повторный прогон на тех же 141 вопросах прошёл допуск ±5% по всем четырём метрикам. Наибольшее относительное отклонение у `answer_correctness`: +4,04% (103 правильных ответа из 141 при повторе, 99 в исходном Excel).
